# HW1 : 計算 2^n 的四種做法與效率比較

以四種不同方式實作 `2^n`，測試指令 `n = 100`，觀察「哪個快、哪個慢、哪個算不出來」。

## 執行方式

```bash
python3 power2n.py
```

## 四種方法

| 方法 | 演算法                       | 呼叫次數 / 時間複雜度 | 說明 |
|------|------------------------------|-----------------------|------|
| 1    | `2 ** n`                     | O(1) (Python 內建)    | C 語言實作的大數運算，直接算出答案 |
| 2a   | `power2n(n-1) + power2n(n-1)` | O(2^n) 次遞迴呼叫     | 每次遞迴都呼叫自己 **兩次**，呼叫次數指數爆炸 |
| 2b   | `2 * power2n(n-1)`           | O(n) 次遞迴呼叫       | 每次遞迴只呼叫自己 **一次**，再乘 2 |
| 3    | 遞迴 + 查表 (memoization)     | O(n) 次遞迴呼叫       | 同 2a 但先查表，算過的結果直接拿來用 |

程式碼參考 `power2n.py`，其中方法 2a 與方法 3 都刻意保留
`power2n(n-1) + power2n(n-1)` 的寫法，差別只在多了一張「查表」。

## 正確性驗證

先以 `n = 20` 驗證四種方法結果全都等於 `2^20 = 1048576`

```
方法1 (2**n)        : True
方法2a (遞迴+遞迴)   : True
方法2b (遞迴*2)      : True
方法3  (遞迴+查表)   : True
全部正確 : True
```

## 效率比較 : n = 100

```
方法1 : 2**n        : 花費 0.000001 秒
方法2a: 遞迴+遞迴    : 超過 5 秒沒算完，強制中止
方法2b: 2*遞迴       : 花費 0.000005 秒
方法3 : 遞迴+查表    : 花費 0.000014 秒

三種算得出來的方法結果都正確 : 1267650600228229401496703205376
```

## 方法 2a 為何算不出來？

方法 2a 每遞迴一次會分裂成兩個呼叫，總呼叫次數約為 `2^(n+1)`，是指數成長。
實測成長趨勢：

```
n= 10  呼叫次數≈2^11≈       2,047 次  花費 0.0000 秒
n= 15  呼叫次數≈2^16≈      65,535 次  花費 0.0015 秒
n= 18  呼叫次數≈2^19≈     524,287 次  花費 0.0127 秒
n= 20  呼叫次數≈2^21≈   2,097,151 次  花費 0.0452 秒
n= 22  呼叫次數≈2^23≈   8,388,607 次  花費 0.1869 秒
```

n 每增加 1，所需時間就**翻倍**。推估到 `n = 100` 約需 `2^101 ≈ 2.5 × 10^30` 次呼叫，
以每秒約 4,500 萬次呼叫估算，要跑 **約 10^21 年**，所以在 n=100 時根本算不出來。

## 結論 (由快到慢)

| 排名 | 方法 | n=100 實測時間 | 時間複雜度 |
|------|------|----------------|------------|
| 1    | 方法1 `2**n`     | 0.000001 秒 | O(1)   |
| 2    | 方法2b `2*遞迴`  | 0.000005 秒 | O(n)   |
| 3    | 方法3 `遞迴+查表` | 0.000014 秒 | O(n)   |
| 4    | 方法2a `遞迴+遞迴` | **算不出來** (超過 5 秒強制中止) | O(2^n)   |

重點：

- **方法 1** 最快，因為底層是 C 語言大數運算，直接一次算完。
- **方法 2b** 每層只遞迴一次，總共 n 次呼叫，很快。
- **方法 3** 雖然寫法跟 2a 一樣 `+自己兩次`，但靠查表讓每個 n 只算一次，速度幾乎等於 2b。
- **方法 2a** 沒有查表，呼叫次數指數爆炸，n 稍微大一點（超過 30）就慢到跑不完，`n = 100` 根本算不出來。
