# HW9 - 搜尋法 (Search Algorithms)

本資料夾包含五個使用「搜尋法」解決的經典問題，涵蓋 **DFS（深度優先搜尋）**、**BFS（廣度優先搜尋）**、**A\*（A-star）** 以及 **貪婪最佳優先搜尋** 等不同策略。

## 搜尋法的共同觀念

搜尋法把問題表示成「狀態空間」（state space）：

- **狀態 (state)**：問題在某一個時刻的情況，例如老鼠的位置、過河時人與物品所在的一岸、棋盤上皇后的擺法。
- **初始狀態 (start)**：搜尋的起點。
- **目標狀態 (goal)**：我們想抵達的狀態。
- **動作 (action) / 轉移 (transition)**：從一個狀態移動到另一個狀態的方法。
- **邊界 (frontier)**：目前還沒展開、等待拜訪的狀態集合。
- **已拜訪 (visited)**：避免重複展開同一個狀態。
- **父節點 (parent)**：記錄每個狀態是從哪裡來的，用來回溯出解答路徑。

不同演算法的主要差別，在於「下一步要先展開哪個狀態」：

- **DFS**：優先往最深處走，走不通再回溯。
- **BFS**：一層一層往外擴散。
- **A\***：依照 `f(n) = g(n) + h(n)` 排序，兼顧已走成本與預估剩餘成本。
- **Greedy Best-First**：只看 `h(n)`，快速但不保證最佳。

## 1. 老鼠走迷宮問題（DFS）

**檔案：`老鼠走迷宮.py`**

### 問題描述

給定一個 8×8 的迷宮，`0` 代表可走的路，`1` 代表牆壁。老鼠從左上角 `(0,0)` 出發，要走到右下角 `(7,7)`，求出任一條可行路徑。

### 方法：深度優先搜尋 + 回溯

DFS 會沿著一個方向一直走，直到碰到牆壁、邊界或已拜訪的格子，才退回上一個格子換方向。

流程：

1. 從起點開始，標記為已拜訪，加入目前路徑。
2. 依序嘗試四個方向（下、右、上、左）。
3. 若某個方向可以走，就遞迴往該方向前進。
4. 若走到終點，回傳整條路徑。
5. 若所有方向都走不通，就把目前格子從路徑中移除（**回溯**），回到上一層。

核心程式片段：

```python
def dfs(pos):
    visited[r][c] = True
    path.append(pos)
    if pos == goal:
        return True
    for dr, dc in DIRECTIONS:
        if dfs((r + dr, c + dc)):
            return True
    path.pop()          # 回溯
    return False
```

### 特性與複雜度

- DFS 不保證找到最短路徑，只保證「若有路就一定找得到」。
- 時間複雜度：`O(V + E)`，在 `R×C` 格子圖中為 `O(R×C)`。
- 空間複雜度：`O(R×C)`，主要來自遞迴堆疊與 visited 陣列。
- 本範例 DFS 展開 19 個節點，找到 19 格的路徑。

## 2. 狼羊甘藍菜過河問題（BFS）

**檔案：`狼羊甘藍菜.py`**

### 問題描述

農夫要帶著狼、羊、甘藍菜從左岸到右岸。船一次只能載農夫和一樣東西，農夫也可以獨自過河。限制是：

- 農夫不在時，狼會吃羊。
- 農夫不在時，羊會吃甘藍菜。

### 狀態表示

用四元組 `(farmer, wolf, goat, cabbage)` 表示狀態，`0` 代表左岸、`1` 代表右岸。

- 初始狀態：`(0, 0, 0, 0)`
- 目標狀態：`(1, 1, 1, 1)`

合法的狀態必須避免「農夫不在場時，天敵與獵物同岸」。

### 方法：廣度優先搜尋

BFS 使用佇列（queue），每次先展開「離起點最少步數」的狀態，因此第一次抵達目標時，一定是最少趟數的解答。

流程：

1. 把初始狀態放入佇列。
2. 從佇列取出一個狀態，檢查是否為目標。
3. 產生所有合法且未拜訪的下一步狀態，記錄父節點與動作後放入佇列。
4. 抵達目標後，沿著父節點回溯，得到完整過河步驟。

### 特性與複雜度

- 在邊權重相同（每步成本為 1）的圖中，BFS 保證最短解。
- 狀態數最多 `2^4 = 16` 種，所以時間與空間複雜度都是 `O(2^4)`。
- 本範例 BFS 拜訪 10 個狀態，找到最少 **7 趟** 過河的解答。

解答步驟：

1. 農夫帶羊過河
2. 農夫獨自過河
3. 農夫帶狼過河
4. 農夫帶羊過河
5. 農夫帶甘藍菜過河
6. 農夫獨自過河
7. 農夫帶羊過河

## 3. 八皇后問題（DFS）

**檔案：`八皇后.py`**

### 問題描述

在 8×8 的棋盤上放置 8 個皇后，使任兩個皇后都不在同一列、同一行、同一條對角線上，求出所有解答。

### 方法：DFS + 回溯 + 剪枝

我們一列一列放皇后：第 `row` 列選擇一個 `col` 放置，然後遞迴處理下一列。

為了快速判斷某個位置是否合法，使用三個集合記錄已被攻擊的欄位與對角線：

- `used_cols`：已使用的行。
- `used_diag1`：已使用的 `row - col` 對角線。
- `used_diag2`：已使用的 `row + col` 對角線。

若某個 `col` 會造成衝突，就**剪枝**，不再往下遞迴。

核心程式片段：

```python
for col in range(n):
    if col in used_cols: continue
    if (row - col) in used_diag1: continue
    if (row + col) in used_diag2: continue

    queens.append(col)
    used_cols.add(col)
    used_diag1.add(row - col)
    used_diag2.add(row + col)

    dfs(row + 1)          # 遞迴下一列

    queens.pop()          # 回溯
    used_cols.remove(col)
    used_diag1.remove(row - col)
    used_diag2.remove(row + col)
```

### 特性與複雜度

- 最壞情況會嘗試 `8^8` 種放法，但透過剪枝後實際只需約數千次遞迴呼叫。
- 本範例 DFS 遞迴呼叫 **2057** 次，總共有 **92** 個解答。
- 時間複雜度：最壞 `O(n!)` 等級（實際因剪枝而大幅降低）。
- 空間複雜度：`O(n)`，來自遞迴深度與三個集合。

## 4. NPC 搜尋玩家問題（A\*）

**檔案：`NPC搜尋玩家.py`**

### 問題描述

在格子地圖中，`NPC` 要找到 `P`（玩家），地圖上有障礙物 `#`，只能上下左右移動。求出 NPC 到玩家的最短路徑。

### 方法：A\* 搜尋

A\* 對每個節點 `n` 計算：

```
f(n) = g(n) + h(n)
```

- `g(n)`：從起點走到 `n` 的實際成本（步數）。
- `h(n)`：從 `n` 到終點的預估成本，本程式使用**曼哈頓距離**：

```python
def manhattan(a, b):
    return abs(a[0] - b[0]) + abs(a[1] - b[1])
```

A\* 使用優先佇列（min-heap），每次取出 `f(n)` 最小的節點展開。

流程：

1. 把起點放入 heap，`g(start) = 0`。
2. 取出 `f` 最小的節點。
3. 若是終點，沿父節點回溯路徑。
4. 否則展開鄰居，更新較小的 `g` 值，並以新的 `f` 放入 heap。
5. 重複直到找到終點或 heap 為空。

### 為什麼曼哈頓距離可以用？

在只能上下左右移動、每步成本為 1 的格子圖中，曼哈頓距離不會高估真實距離（**admissible**），因此 A\* 保證找到最短路徑。

### 特性與複雜度

- 時間複雜度：最壞 `O(E log V)`，其中 `E` 是邊數、`V` 是節點數；效能高度依賴 heuristic。
- 空間複雜度：`O(V)`，需要儲存 `g`、`parent`、`closed` 與 heap。
- 本範例 A\* 展開 42 個節點，找到 18 步的最短路徑。

## 5. IC 設計中的電路繞線問題

**檔案：`電路繞線.py`**

### 問題描述

在 IC 設計中，繞線（routing）要把晶片上的多條連線（net）連接起來，同時避開元件、其他連線與障礙物。可以把它想像成在格子圖上找路徑：`'.'` 是可繞線區域，`'#'` 是障礙物。

本程式比較三種方法，並示範多條 net 的循序繞線。

### 方法一：Lee 演算法（BFS 波浪擴散）

Lee 演算法就是格子圖上的 BFS：

1. 從起點開始，把相鄰且可走的格子標上距離 1。
2. 再從距離 1 的格子往外標距離 2，像波浪一樣擴散。
3. 抵達終點後，從終點沿著距離遞減的方向往回走，得到最短路徑。

優點是保證最短穿線路徑；缺點是會拜訪大量節點，記憶體與時間成本較高。

### 方法二：A\* 繞線

A\* 在 Lee 的基礎上加入 heuristic（曼哈頓距離），優先往終點方向搜尋，通常可以減少展開的節點數。只要 heuristic 不高估，仍然保證最短穿線路徑。

### 方法三：貪婪最佳優先搜尋 (Greedy Best-First Search)

貪婪搜尋只看 `h(n)`，每次選擇「看起來離終點最近」的節點。速度通常很快，但可能繞遠路，**不保證最短穿線路徑**。

### 方法四：循序繞線 (Sequential Routing)

實務上會有多條 net。循序繞線的做法是：

1. 先繞第一條 net。
2. 把第一條 net 使用過的格子標記為已被佔用。
3. 再繞第二條 net，此時必須避開已被佔用的格子。
4. 重複直到所有 net 都繞完。

本程式在繞某一條 net 時，會保留其他 net 的端點，避免一條線直接穿過別人的接腳。若某條 net 繞線失敗，實務上會使用 **rip-up and reroute（拆線重繞）**：把造成阻塞的線拆掉，換一條路徑後再重試。

其他常見的進階方法還包括：

- **Rip-up and reroute**：拆掉部分連線重新繞線。
- **Negotiated congestion routing**：允許暫時共用資源，再逐漸提高擁塞成本。
- **Multilayer routing**：使用多層金屬層，透過 via 連接不同層。
- **Global routing + Detailed routing**：先做粗略的整體規劃，再進行細部繞線。

### 執行結果

單一 net 的比較（12×12 地圖，起點 `(0,0)`，終點 `(11,11)`）：

| 方法 | 路徑長度 | 展開節點數 | 是否保證最短 |
|------|----------|------------|--------------|
| Lee (BFS) | 22 步 | 117 | 是 |
| A\* | 22 步 | 117 | 是 |
| Greedy Best-First | 28 步 | 32 | 否 |

在這個例子中，A\* 與 BFS 展開的節點數相同，原因是地圖中的障礙物造成許多 `f` 值相同的節點，且 heuristic 的引導效果有限。不過在較開放或較大的地圖中，A\* 通常能明顯減少展開節點數。

多條 net 循序繞線結果：

- net 1：`(1,1) -> (10,10)`，路徑長度 18 步。
- net 2：`(1,10) -> (10,1)`，路徑長度 22 步。
- 第二條 net 成功避開第一條 net 已使用的格子與對方的接腳。

## 五種方法的比較

| 演算法 | 主要資料結構 | 是否保證最短 | 適用情境 |
|--------|--------------|--------------|----------|
| DFS | 堆疊 / 遞迴 | 否 | 只要找任一條路徑、需要回溯枚舉所有解（如八皇后） |
| BFS | 佇列 | 是（邊權重相同時） | 最短步數、狀態數不大的問題（如過河問題） |
| A\* | 優先佇列 (heap) | 是（heuristic 可採納時） | 有明確終點、可設計 heuristic 的路徑搜尋 |
| Greedy Best-First | 優先佇列 (heap) | 否 | 需要快速得到可行解、可接受非最佳解 |
| Lee 演算法 | 佇列 | 是 | 電路繞線、格子圖最短路徑 |

## 結論

- **DFS** 適合「找任一解」或「枚舉所有解」，搭配回溯與剪枝可以解決八皇后這類組合問題，但不保證最短路徑。
- **BFS** 在每一步成本相同時保證最短解，很適合狀態數不多的問題，例如狼羊甘藍菜。
- **A\*** 透過 `g + h` 兼顧實際成本與預估成本，在路徑搜尋問題中通常比 BFS 更有效率，且只要 heuristic 可採納就能保證最佳解。
- **貪婪搜尋** 速度快，但可能得到較差的解，適合需要即時反應的情境。
- **IC 繞線** 可以視為格子圖上的路徑搜尋問題，實務上會結合 Lee、A\*、循序繞線、拆線重繞與多層繞線等技術，在路徑品質與執行效率之間取得平衡。
